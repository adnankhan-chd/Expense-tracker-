# Expense-tracker-# Personal Expense Tracker

A multi-user expense tracker built with **Reflex**, **Firebase Firestore**, **Firebase Authentication** and optional **Google Gemini** insights.

> **Status:** written without being able to install dependencies or run the app in the authoring environment. Follow the verification checklist at the end before relying on it.

## 1. Overview and features

- Email/password sign-up and sign-in; each user sees only their own data
- Full CRUD: add, view, edit, delete (with confirmation dialog)
- Fields: title, amount (exact decimal), currency (default PKR), category, date, payment method, notes, created/updated timestamps
- Search (title/notes), category filter, date range, sort by date or amount
- Totals and category-wise summary (per selected currency, respects filters)
- Empty states, loading indicators, success toasts, clear error messages
- Optional AI insights from Gemini, based only on aggregated totals

## 2. Stack and architecture

| Layer | Technology |
|---|---|
| UI / state | Reflex |
| Database | Cloud Firestore via `firebase-admin` (server side only) |
| Auth | Firebase Auth (Identity Toolkit REST API, ID token verified with Admin SDK) |
| AI | Google Gen AI SDK (`google-genai`) |
| Config | `python-dotenv` |

**Key design decision:** the browser never talks to Firestore. All database access runs on the Reflex server using the Admin SDK. The Admin SDK bypasses Security Rules, so isolation is enforced in code: every document lives at `users/{uid}/expenses/{id}`, and `uid` comes only from a server-verified ID token held in a backend-only state variable.

`app.py` is split into numbered sections: config, Firebase init, validation, Firestore CRUD, auth, dashboard calculations, Gemini, Reflex state, UI.

Firestore layout:

```
users/{uid}/expenses/{expenseId}
  title, amount (string, e.g. "1250.00"), currency, category,
  date ("YYYY-MM-DD"), payment_method, notes, created_at, updated_at
```

## 3. Prerequisites

- Python 3.11 (3.10+ should work; Reflex also needs Node.js, which Reflex can download itself)
- A Google account and a Firebase project

## 7. Firebase setup

1. Go to the [Firebase console](https://console.firebase.google.com) and create a project.
2. **Build > Firestore Database > Create database** (production mode, choose a region).
3. **Build > Authentication > Get started > Sign-in method > Email/Password > Enable**.
4. **Project settings > General**: copy the **Web API key** into `FIREBASE_WEB_API_KEY`.
5. **Project settings > Service accounts > Generate new private key**. Save the JSON file **outside the project folder** or in a git-ignored location, and set `FIREBASE_CREDENTIALS_PATH` to its path.

## 8. Security rules

The app uses only the Admin SDK, so clients should have **no direct access**. Publish these rules (Firestore > Rules):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

The Admin SDK is unaffected by rules. If you later add direct client access, use owner-only rules instead:

```
match /users/{uid}/expenses/{expenseId} {
  allow read, write: if request.auth != null && request.auth.uid == uid;
}
```

## 9. Gemini setup

Create a key in [Google AI Studio](https://aistudio.google.com/apikey) and put it in `GEMINI_API_KEY`. Without a key, AI features are hidden and everything else works.

## 10. `.env.example`

Copy to `.env` and fill in your own values (placeholders only):

```env
# Firebase (server-side)
FIREBASE_CREDENTIALS_PATH=C:\secrets\your-service-account.json
# Alternative for hosting: raw JSON or base64 of the JSON (overrides nothing; path is used if this is empty)
FIREBASE_CREDENTIALS_JSON=
FIREBASE_WEB_API_KEY=your-firebase-web-api-key

# Gemini (optional)
GEMINI_API_KEY=your-gemini-api-key
GEMINI_MODEL=gemini-2.5-flash
AI_ENABLED=true

# App behaviour
DEFAULT_CURRENCY=PKR
SUPPORTED_CURRENCIES=PKR,USD,EUR,GBP,AED,SAR,INR
REQUEST_TIMEOUT_SECONDS=20
AI_COOLDOWN_SECONDS=10
```

## 11. Environment variables

| Variable | Purpose |
|---|---|
| `FIREBASE_CREDENTIALS_PATH` | Path to the service-account key file |
| `FIREBASE_CREDENTIALS_JSON` | Alternative: the key as JSON or base64 (for hosts without files). If both are set, this one wins |
| `FIREBASE_WEB_API_KEY` | Used server-side to sign users in/up |
| `GEMINI_API_KEY` | Enables AI insights |
| `GEMINI_MODEL` | Model name (default `gemini-2.5-flash`) |
| `AI_ENABLED` | `true`/`false` master switch for AI |
| `DEFAULT_CURRENCY` | Default currency (default `PKR`) |
| `SUPPORTED_CURRENCIES` | Comma-separated currency codes shown in the UI |
| `REQUEST_TIMEOUT_SECONDS` | Timeout for Firebase, Auth and Gemini calls |
| `AI_COOLDOWN_SECONDS` | Minimum gap between AI requests per session |

## 13. Using CRUD

- **Add:** *Add expense*, fill the form, *Save*. Invalid input shows a message and nothing is written.
- **Edit:** pencil icon, change fields, *Save*. The same document is updated (no duplicate).
- **Delete:** trash icon, then confirm. Nothing is deleted until you confirm.
- **Search/filter/sort:** use the *Search, filter & sort* card. Totals and the category summary follow the filters.

## 14. AI features

- Disable with `AI_ENABLED=false` (or leave `GEMINI_API_KEY` empty).
- Insights run only when you click *Get insights*, with a cooldown between requests.
- Only category totals for the chosen period and the previous comparable period are sent. Titles and notes are never sent.
- Gemini cannot create, edit or delete expenses; output is shown as text only and labelled as an AI-generated estimate.

## 15. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| "Configuration incomplete" banner | Missing `.env` values; restart `reflex run` after editing |
| "Firebase credentials file was not found" | Wrong `FIREBASE_CREDENTIALS_PATH` |
| "Email/password sign-in is not enabled" | Enable it in Firebase Authentication |
| "Not found ... database has not been created" | Create the Firestore database |
| "Firestore denied the request" | Service account lacks Firestore access; use the key from this project |
| Sign-in works but "Could not verify your sign-in" | System clock out of sync, or credentials from a different project than the Web API key |
| AI "rejected" | Check `GEMINI_API_KEY` and `GEMINI_MODEL` |
| AI "rate-limited" | Wait and retry |
| Import/API errors on start | Reflex changes quickly; install the versions in `requirements.txt` |

## 16. Security and deployment notes

- Never commit `.env` or the service-account key (add both to `.gitignore`). Rotate the key if it leaks.
- The Admin credential stays on the server; only rendered UI data reaches the browser.
- Serve over HTTPS in production and restrict who can reach the server.
- Consider API-key restrictions for the Web API key and quota limits for Gemini.
- Logs avoid secrets and expense contents; keep it that way when extending.
- Per-session login: refreshing the tab usually keeps the session, but a server restart signs users out.

## 17. Known limitations and future work

- Loads all of a user's expenses in one read and filters in memory: fine for thousands of records, not for very large histories (add Firestore queries and pagination).
- Totals are per currency; no currency conversion.
- No password reset, email verification or social login.
- No CSV export, recurring expenses, budgets or charts (category bars are simple progress bars).
- Reflex needs the `reflex init` layout, so `app.py` must be copied into the package folder.
- Not yet covered by automated tests; add `pytest` tests for the pure functions in sections 3 and 6.

6. Delete: Cancel keeps it, Delete removes it.
7. Restart the server, sign in: data is still there.
8. Second account cannot see the first account's expenses.
